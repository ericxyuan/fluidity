# Fluidity Motion

Read [motion policy](references/motion-policy.md) before choosing animation behavior.
It is the shared decision authority for every Fluidity skill. Check actual task,
frequency, modality and existing motion tokens before adding movement.

Use [gesture mechanics](references/gesture-mechanics.md) for drag, swipe, springs,
momentum, boundaries and cancellation. Use [recipes](references/recipes.md) for CSS,
presence, measured layout, shared elements, text and coordinated transitions.
Use [vocabulary](references/vocabulary.md) for naming an effect; a naming request
needs a precise term and brief explanation, not an implementation project.

For complete UI primitives, use [component selection](../fluidity-components/SKILL.md)
to preserve semantics and focus behavior. Motion is a behavior layer, not a substitute
for a working dialog, tab list, slider or button.

Implement within the authorized scope. Test interruption, rapid toggling, keyboard,
reduced motion and actual content resizing when relevant. Explain material decisions
briefly: purpose/frequency, mechanism, timing or spring parameters and what was tested.
When feel remains unverified, name the specific observation still required.
